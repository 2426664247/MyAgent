# AGENTS.md

This file is for future coding agents working on AgentV2.

## Project Summary

AgentV2 is a local coding agent with a CLI and a FastAPI-hosted React web UI. It uses OpenAI-compatible chat completions, native function calling, and a small set of sandboxed tools for file inspection, file writes, and confirmed shell commands.

The project is intentionally local-first. Web sessions are saved as JSON in `~/.agent_v2/sessions/`, while model settings can be saved to the package-local `.env` through the web settings dialog.

## Repository Boundaries

Work inside this repository only. Do not include parent-folder experiments, reports, temporary target projects, or local test directories when publishing.

Never commit:

- `.env`
- real API keys or tokens
- local session JSON from `~/.agent_v2/sessions/`
- `node_modules/`
- `.pytest_cache/`, `__pycache__/`, `*.pyc`
- `*.tsbuildinfo`
- local absolute paths or personal machine/user names

Static assets under `static/` are generated by the frontend build and are intended to be committed when publishing a ready-to-run version.

## Common Commands

Install Python package:

```bash
pip install -e .
```

Run the web app:

```bash
python -m agent_v2.web --host 127.0.0.1 --port 8000
```

Run the CLI:

```bash
python -m agent_v2 /absolute/path/to/project
```

Run backend tests from the repository root after installing the package in editable mode:

```bash
pip install -e .
python -m unittest discover -s tests -v
```

Rebuild frontend:

```bash
cd web_ui
npm install
npm run build
```

## Backend Rules

- Keep the web session working directory explicit. Do not add a default project directory.
- `POST /api/sessions` must reject empty project paths and relative paths.
- `validate_project_dir()` should continue to reject missing paths and files.
- File and shell tools must continue to use `PathSandbox`.
- `run_command` must require confirmation in both CLI and web flows.
- Web streaming should keep assistant messages separate:
  - stream visible text through `assistant_delta`
  - stream reasoning through `reasoning_delta`
  - persist a completed assistant bubble on `assistant_message_complete`
  - treat `final` as a status event, not as a merged transcript message
- Preserve stop behavior through `/api/sessions/{id}/stop`.
- Keep settings compatible with OpenAI-style providers and DeepSeek defaults.

## Frontend Rules

- The main transcript should show user and assistant chat bubbles only.
- Reasoning should be displayed separately from the assistant answer, preferably in a compact collapsible block.
- Do not dump backend tool logs into the main chat stream.
- Keep command confirmation visible and explicit before running shell commands.
- New sessions must ask for an existing absolute project directory. Do not imply relative paths are accepted.
- Rebuild `static/` after editing `web_ui/`.

## Architecture Notes

- `settings.py`: resolves model settings from environment variables.
- `env_config.py`: reads, masks, and writes `.env`.
- `llm.py`: wraps the OpenAI-compatible client, streaming, tool calls, fallback parsing, and reasoning extraction.
- `registry.py`: provides `@tool()` registration and JSON Schema generation.
- `runner.py`: synchronous CLI ReAct loop.
- `web_runner.py`: async web runner with SSE events and command confirmation broker.
- `web.py`: FastAPI routes, session persistence integration, static hosting, and SPA fallback.
- `sessions.py`: JSON-backed session storage and project directory validation.
- `sandbox.py`: path containment checks.
- `builtins/fs.py`: file tools.
- `builtins/shell.py`: confirmed command execution.
- `web_ui/`: React + TypeScript source.
- `static/`: built frontend served by FastAPI.

## Verification Expectations

After backend changes, run:

```bash
pip install -e .

```

After frontend changes, run:

```bash

npm run build
```
